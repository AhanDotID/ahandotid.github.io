Exposing 350 Enterprise Customers via BuddyBoss REST API - WordPress VIP

📅 2026 ⏱ 6 min read 🎯 HackerOne - WordPress VIP 👤 Ahan Pahlevi

The Story

It started like any other recon session - just me, a browser, and a WordPress site. I was poking around customerhub.wpvip.com, the customer hub for WordPress VIP - one of the most premium managed WordPress hosting platforms, used by enterprise companies like Disney, Salesforce, and CNN.

I noticed the site was running BuddyBoss, a popular plugin for building community/membership platforms. BuddyBoss registers its own REST API routes under /wp-json/buddyboss/v1/. That endpoint immediately caught my attention. REST APIs are always interesting to poke at.

So I registered a basic account, waited for approval (about 1-2 business days), logged in, and started exploring what the API would give me.

Registration page - basic account, waiting for approval before accessing the hub

Finding the Vulnerability

First thing I tried: hit the /members endpoint after authentication. To do that, I needed a valid REST API nonce - which WordPress conveniently embeds in the page source inside the BB_Nouveau_Presence JavaScript variable.

Ctrl+U → search "rest_nonce" → found inside BB_Nouveau_Presence variable

Once I had the nonce, I fired a simple authenticated GET request:

GET /wp-json/buddyboss/v1/members?per_page=100 HTTP/2
Host: customerhub.wpvip.com
Cookie: wordpress_logged_in_[hash]=[value]
X-WP-Nonce: [nonce_value]

The server came back with HTTP 200 - and a response body packed with member data. Not just names. Full PII. Then I checked the response headers and saw something that made my jaw drop: 

x-wp-total: 350
x-wp-totalpages: 350

x-wp-total: 350 - all enterprise customers fully enumerable by any basic account

350 enterprise customers. Fully enumerable. By anyone who could get a basic account approved. No special role. No admin access. Just a freshly registered account.

Impact Analysis

This wasn't just "names and emails." These are enterprise customers - companies paying thousands per month for WordPress VIP. With a single API call, an attacker could:

  • Enumerate all 350 enterprise customers - full name, username, company, job role, location, customer type, last activity timestamp
  • Business intelligence leak - competitors can identify every WordPress VIP client in one request
  • Spear phishing - name + company + job role = perfect profile for targeted attacks against high-value enterprise targets
  • Privacy violation - users never consented to having their data queryable by any newly approved account

The Response

I submitted the report to WordPress VIP's HackerOne program and waited. A few days later, I got this back:

"Hi, Thanks for sending this in. This is a community directory and is supposed to show all this information / profiles of other members. This is not a security issue. All the best." - ehtis, WordPress VIP Triager

And just like that - marked as Informative, severity: none.

Honestly? I disagree. A community directory is fine - if users know their data is visible and actually consent to it. But enterprise customers joining a customer hub likely don't expect their company name, job role, and full name to be bulk-queryable via a REST API by any newly approved account. That's an expectation vs. reality gap - and that gap is exactly what attackers exploit.

But that's bug bounty. You document it, you learn from it, you move on. 🤷

Suggested Remediation

  • Implement role-based access control on /wp-json/buddyboss/v1/members - restrict to admins or authorized roles only
  • Strip sensitive xprofile fields from API responses for non-admin users
  • Add rate limiting to prevent bulk enumeration
  • Give users granular privacy controls - let them choose what's visible in the directory

Lessons Learned

Always check third-party plugin REST API endpoints. BuddyBoss, WooCommerce, LearnDash - these plugins register their own routes that often inherit weaker access controls than core WordPress. The /wp-json/ directory is a goldmine. And response headers like x-wp-total can immediately reveal the scale of a finding before you even dig into the response body. Keep hunting.
